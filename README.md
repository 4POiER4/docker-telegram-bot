# Telegram-бот для мониторинга Docker

Бот отвечает на `/status` в личном чате. Он сообщает, когда выбранный контейнер остановился, пропал, перестал проходить Docker healthcheck, начал часто перезапускаться или восстановился. Повторяющееся состояние не вызывает новое сообщение. При изменении состояния бот отправляет новое уведомление.

Сборщик опрашивает Docker примерно раз в 10 секунд. Порог частых перезапусков — 3 автоматических перезапуска Docker за 5 минут после начала наблюдения. Состояние healthcheck доступно для контейнеров с настроенной проверкой. Для остальных бот показывает состояние процесса. Если целиком отключится сервер или пропадёт его интернет, для немедленного оповещения понадобится внешний мониторинг.

## Запуск на сервере

Нужен Linux-сервер с Docker Engine, Docker Compose (`docker compose`), доступом к Docker Hub для сборки образа и исходящим HTTPS к `api.telegram.org`. Зайди на сервер по SSH, клонируй репозиторий или распакуй архив и перейди в каталог `docker-telegram-bot`. Команды ниже рассчитаны на Bash. Если на сервере Docker доступен только через `sudo`, используй `sudo` для всех команд Docker.

1. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot` и получи токен нового бота. Запиши токен на сервере через этот запрос. Ввод скрыт.

   ```bash
   mkdir -m 700 private
   read -rsp 'Токен от BotFather: ' bot_token
   printf '\n'
   printf '%s\n' "$bot_token" > private/telegram_token
   unset bot_token
   chmod 644 private/telegram_token
   ```

   Каталог `private` доступен владельцу на сервере. Compose монтирует только файл токена, а режим `644` позволяет боту внутри контейнера прочитать его от непривилегированного пользователя.

2. Найди точные имена контейнеров в колонке `NAMES` и укажи их в `WATCH_CONTAINERS` через запятую. В `SERVER_NAME` можно задать подпись для сообщений.

   ```bash
   docker ps -a
   cp .env.example .env
   nano .env
   ```

3. Привяжи свой личный чат. Открой ссылку, которую выведет команда, и нажми «Запустить». Скопируй число из строки «ID личного чата» в `TELEGRAM_CHAT_ID` в файле `.env` вместо `0`.

   ```bash
   docker compose run --rm --no-deps --build bot python bot.py chat-id
   nano .env
   ```

4. Запусти мониторинг. В Telegram отправь своему боту `/status`.

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

Бот отвечает в разрешённых личных чатах и отправляет автоматические оповещения в `TELEGRAM_CHAT_ID`. Все соединения с Telegram исходящие, поэтому пробрасывать порт на сервере не нужно. К Docker-сокету подключается сборщик без сетевого доступа. Бот читает через общий том только состояние выбранных контейнеров и счётчики перезапусков.

## Доступ к статусу для коллег

На время привязки останови бота, чтобы команда `chat-id` могла получить ответ от Telegram.

```bash
docker compose stop bot
docker compose run --rm --no-deps --build bot python bot.py chat-id
```

Передай одноразовую ссылку коллеге и попроси его открыть её в Telegram и нажать «Запустить». Добавь выведенное число в `TELEGRAM_STATUS_CHAT_IDS` в своём `.env`. Для нескольких коллег перечисли ID через запятую, например `TELEGRAM_STATUS_CHAT_IDS=123456789,987654321`. Сохрани свой ID в `TELEGRAM_CHAT_ID`. Затем запусти бота и попроси коллегу отправить `/status` в личном чате с ним.

```bash
docker compose up -d --build bot
```

## Проверка уведомлений

Чтобы проверить остановку и восстановление без вмешательства в работающие приложения, запусти временный контейнер.

```bash
docker run -d --name monitor-demo alpine:3.23 sleep 3600
```

Добавь `monitor-demo` в `WATCH_CONTAINERS` в файле `.env` и выполни `docker compose up -d`. Отправь `/status`, дождись состояния «работает», затем выполни `docker stop monitor-demo`. После сообщения об остановке запусти `docker start monitor-demo` и дождись сообщения о восстановлении.

После проверки убери `monitor-demo` из `WATCH_CONTAINERS`, выполни `docker compose up -d`, затем удали временный контейнер командой `docker rm -f monitor-demo`.

## Если бот не отвечает

```bash
docker compose ps
docker compose logs --tail=80 bot collector
```

- Если при привязке возникла ошибка Telegram 409, проверь, что этот токен используется только этим ботом и у него нет активного webhook.
- Если есть проблемы с Docker-сокетом, проверь его путь. Для нестандартного расположения задай `DOCKER_SOCKET` в `.env` и выполни `docker compose up -d`.
- Если бот уже запущен и нужно заново привязать чат, сначала выполни `docker compose stop bot`, затем повтори шаги 3 и 4.

Справка по созданию ботов и получению сообщений доступна в [документации Telegram](https://core.telegram.org/bots/features#botfather).
